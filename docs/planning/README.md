# Product planning

These documents contain accepted product targets, not claims that all listed
features are implemented. `BACKLOG.md` remains authoritative for task owner,
status, and milestone. Keep each plan consistent with its owning backlog rows
and the accepted architecture decisions.

| Plan | Purpose |
|---|---|
| [Tool adapters](tool-adapters.md) | Future public tool names, capability detail, adapter taxonomy, security, and resource constraints. |
| [Runtime modes](runtime-modes.md) | Direct STDIO, local proxy/auto, and operating-system service targets. |
| [Efficiency](efficiency.md) | Payload, catalog, latency, resource, and benchmark requirements. |
| [Release scope](release-scope.md) | Required Version 1.0 work and deliberately deferred capabilities. |

See the [roadmap](../roadmap.md) for workstream orientation and the
[backlog](../../BACKLOG.md) for canonical implementation ownership. Accepted
plans do not authorize unrelated implementation, installation, credentials,
remote operations, or release actions.

Personal work queues, individual review batches, and execution reports are
not product plans and are kept outside this public documentation tree.
Removing such a report does not implement a feature or close a finding.
